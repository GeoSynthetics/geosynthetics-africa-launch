    Dynamic Page Templates & Admin Integration

    A comprehensive manual on creating, editing, deleting dynamic product category pages and linking them to the recursive site megamenu.

    Overview & Architecture

    The Geosynthetics Africa platform employs a highly flexible, data-driven approach to product page creation. Rather than hardcoding structural pages, administrators can visually build and update product categories directly from the admin panel.

    The connection is fully unified: when an admin modifies values in the 12-tab Page Templates visual builder, changes are saved to Supabase and immediately pushed to the public website, rendering custom titles, specifications tables, FAQs, highlight badges, and installation warnings in real-time.

    Supabase Config Backing

    All template configurations live in the site_config table under the key template_product_categories as a single JSON object. This eliminates complex schema migrations while keeping data atomic and highly cached.

    Zero-Downtime Seeding

    If the database is clean, visiting the admin template page prompts the user to "Seed Defaults" which populates all 8 canonical geomembrane types (HDPE, LLDPE, PVC, EPDM, PP, Textured, Speciality, and Floating Covers).

    Category Alignment

    Protects parent categories (e.g. Geomembranes) by blocking them in Page Templates. Instead, editing their layout content is done directly in the Site Builder, where custom inputs dynamically merge onto premium fallback layouts.

    Administrator Notice
    Access to both Page Templates and Site Builder is restricted to verified administrators and staff. Attempting to access these pages without appropriate session roles will redirect to the secure login gateway.

    Creating a Page Template

    Adding a brand-new dynamic sub-category is fully streamlined. Follow this step-by-step procedure to add a page correctly:

    1

    Access Page Templates

    Log into the admin portal using your credential console. Once inside, locate and click the Product Page Templates item from the administration navigation menu or visit /admin/page-templates.

    2

    Initialize a New Slug

    In the left sidebar of the templates builder, click the + New Template button. A small text input will appear inside the sidebar area.

    3

    Enter Slug Name

    Type in the exact lowercase URL-safe slug for your product sub-page (e.g. custom-clay-liners). Ensure you use only alphanumeric characters and hyphens. Click Create to initialize local defaults.

    4

    Build Out Content & Save

    The template is added instantly. Now, go tab by tab (Hero, Description, FAQs, Table) and fill in your values. Once finished, click the glowing Save All button in the top right header to commit it to Supabase.

    Editing Page Contents

    Editing page contents is fully structured into 12 visual tabs. Select your target category from the sidebar and use the designated sub-panels:

    Properties & Specs Table

    Located in the Properties Table tab. Build a robust grid of physical specs. You can dynamically click + Column to add new test vectors (e.g. "Metric Value", "Imperial Value") or + Row to add custom polymer test properties (e.g. "Puncture Resistance").

    Badge Callouts

    Managed in the Highlights tab. Configure a set of micro key-value pairs (e.g., "Standard Roll: 7.0m", "Warranty: 20 years"). These are automatically compiled into visual pill badges that render prominently under the H1 page header.

    FAQs Accordion

    Located in the FAQs tab. Add recursive question and answer sections. Administrators can easily update pricing guidance, welding tolerances, or storage procedures which customers can slide open instantly.

    Cross-Linking Products

    Located in the Products tab. Link actual items from the primary catalog by entering their exact product names, short descriptions, and technical links. These render as product recommendations at the bottom of the page.

    Pro Tip: Real-time Live Preview
    Unsaved changes are clearly marked with an amber ● Unsaved indicator. You can preview your work at any time by clicking the Preview button in the active category header bar. This launches the exact draft in a separate browser tab before committing the save.

    Deleting a Template Page

    If a product line is discontinued or consolidated, you can easily purge its dynamic template configuration from the platform:

    1

    Hover Target Template

    Locate the template you wish to delete in the left sidebar of the templates builder interface.

    2

    Trigger purges

    Click the red Trash Icon that dynamically fades in next to the template label on hover. This triggers an Alert Dialog window.

    3

    Confirm and Commit

    Confirm the action inside the alert box. Lastly, click the global Save All button in the top right corner. The database record is immediately purged, and the public route will safely output a clean 404 response.

    Linking to Mega Menu

    Creating a new template page doesn't automatically publish it in the navigation headers. To make your new page accessible to public users, you must register it in the megamenu hierarchy. Thanks to our unified system, this is now a simple **1-click automatic action**:

    1

    Check Menu Status Pill

    Look at the active template header bar inside the Page Templates page. If the template is not in the menu, you will see a warning pill: ✕ Unlinked (Hidden from Nav Menu).

    2

    Link Instantly

    Click the glowing ⚡ Link to Menu action button right next to the status pill. A dialog box will appear asking you to choose the parent menu category.

    3

    Select Parent & Confirm

    Select the desired parent group (e.g. Geomembranes or Geotextiles) from the dropdown list and click Confirm Link. The system will automatically build the required JSON structures, resolve parameters, purge old duplicate paths, register the link in Supabase, and update the status pill to green instantly!

    Alternative: Site Builder Autocomplete
    If you are already inside the Site Builder (/admin/site-builder) configuring links, you don't need to manually type labels or path names. Simply add/select a tree node, locate the ⚡ Auto-fill from Page Template panel under the Identity tab, and pick your template. All parameters will instantly auto-populate without any risk of spelling errors or 404s!

    Technical & Architecture Reference

    For software engineers and AI coding agents extending this codebase, please adhere to the following architecture rules and structures:

    1. Strict TanStack Router/Page Separation

    In order to allow TanStack Router to properly code-split routes into light chunks and prevent warning console logs during bun dev, never export page JSX components directly from route files. Route files must only configure createFileRoute, while the full JSX live separately in pages. 

    // ❌ AVOID - exporting component from route file breaks code-splitting
export function ProductCategoryPage() { ... }
export const Route = createFileRoute("/products/$category")({ component: ProductCategoryPage });

// ✅ CORRECT - route configuration file only exports Route config
import { ProductCategoryPage } from "@/pages/ProductCategoryPage";
export const Route = createFileRoute("/products/$category/")({
  loader: async ({ params }) => { ... },
  component: ProductCategoryPage
});

    2. Supabase Integration Hooks

    Fetching from Supabase uses cached loaders and helper APIs. The core function is getProductPageContent(slug), located in src/data/product-pages.ts. It fetches custom family templates, but also seamlessly resolves parent categories by querying the visual hierarchy tree (hierarchy_products) and merging site builder customizations onto premium default layouts: 

    export async function getProductPageContent(slug: string): Promise<ProductPageContent | null> {
  // 1. Query custom templates for product family sub-pages
  const { data } = await supabase
    .from("site_config")
    .select("value")
    .eq("key", "template_product_categories")
    .maybeSingle();

  if (data?.value?.[slug]) {
    return data.value[slug] as ProductPageContent;
  }

  // 2. Dynamic fallback logic for the 8 parent product categories
  const parentCategories = ["geomembranes", "geotextiles", "geogrids", "geocells", "gcls", ...];
  if (parentCategories.includes(slug)) {
    const fallback = generateParentCategoryFallback(slug);
    
    // Merge customized elements edited inside the Site Builder tree
    const { data: hierarchyData } = await supabase
      .from("site_config")
      .select("value")
      .eq("key", "hierarchy_products")
      .maybeSingle();
      
    if (hierarchyData?.value?.items) {
      const matched = hierarchyData.value.items.find((i: any) => i.slug === slug);
      if (matched?.pageContent) {
        return { ...fallback, ...matched.pageContent };
      }
    }
    return fallback;
  }
  return null;
}

    3. Unified Parent Categories vs. Sub-Page Templates

    To prevent data duplication and configuration conflicts, the platform enforces a strict separation between parent landing pages and sub-page/family templates:

    • Parent Category Pages: The 8 root product categories (e.g. /products/geomembranes, /products/geotextiles) are governed inside the Site Builder visual hierarchy tree. Admin customizations in the Site Builder are merged onto premium fallback layouts.
    • Sub-Page Templates: Detailed family sub-pages (e.g. /products/geomembranes/hdpe-geomembranes) are governed inside Page Templates. Parent category slugs are strictly protected from creation here to prevent layout/navigation loop issues.

    4. XML Sitemap & SEO Discovery

    The dynamic sitemap at /sitemap.xml is auto-generated by a TanStack Start server route located in src/routes/sitemap[.]xml.ts. It automatically queries `template_product_categories` and includes all dynamic admin-created categories seamlessly, ensuring instant Google discovery without manual updates.
